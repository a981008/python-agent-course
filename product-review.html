三、跨维度高优先级发现（去重后 Top 7）

高 · 视觉+体验+工程默认「自动主题」在系统深色下只做了一半，对比度崩坏
变量层用 @media(prefers-color-scheme:dark) 变暗，但高亮 token 只在 [data-theme="dark"] 覆盖；theme.js 在 auto 下移除该属性 → 关键字 tk-kw 落在暗底 #26241f 仅 2.54:1（FAIL），fn 3.72、num 3.78、str 4.36 均不达标。核心按钮白字 #fff / --accent #d29a6b = 2.45:1（FAIL）。波及全部 23 页。
建议：token 暗色规则扩到 @media(prefers-color-scheme:dark) :root:not([data-theme=light])；新增 --on-accent（暗色取 #1b1916，7.16:1）供按钮/toast 使用。⚠️ 见第六节修复顺序约束。
高 · 工程0007 练习场 9 道代码题完全无法判分（确定性功能回归）
0007-modules-drill.html:676 调用 ensurePy()，但全文件无定义（其余 8 个 drill 均各有一处）。9 道代码题点「检查」时 ReferenceError 被同行 catch 捕获，界面直接显示 ensurePy is not defined。
建议：从 0003 复制 ensurePy 块补回，或统一引擎后重生成 0007；补静态断言「含代码题的页面必须定义 ensurePy」。
高 · 体验进度追踪与实际学习行为脱节
quiz 答对、py-lab 通过、review 通过都不更新大纲状态芯片；各模块各存各的 localStorage——quiz.js 派发 quiz:answered 无消费方，drill 用 lesson-0003-drill-progress，大纲读 wb-lesson-status-v1。用户必须手动回大纲点芯片。间隔复习无调度与持久化，刷新即失。
建议：定义统一进度事件，让「本课 py-lab 全绿 + 复习通过」自动标记主课完成；复习存时间戳并在大纲显示「今日待复习 X 题」。
高 · 体验+工程键盘路径基本不可用：Tab 被困 + 焦点态与反馈缺失
pyhl.js 对所有 Tab（含 Shift+Tab）无条件 preventDefault 插 4 空格，键盘用户无法从代码框跳到运行/检查按钮（违反 WCAG 2.1.2）；:focus-visible 全站仅 1 处，编辑器 outline:none 无替代；review/drill/py-lab 状态区与 quiz 结果均无 aria-live，读屏用户点「检查」后感知不到结果——而这是产品最核心的即时反馈。
修复前现实降级：仅能用 Ctrl/Cmd+Enter 原地触发运行/检查，或用鼠标点按钮；看完反馈要跳下一题仍离不开鼠标——对纯键盘用户此路径完全阻断。
建议：Tab 处理加 if(e.shiftKey)return; 让 Shift+Tab 走原生，并补 Esc 解锁，仅插 4 空格时拦截；全局加 :focus-visible{outline:2px solid var(--accent)}；反馈节点加 aria-live="polite"（错误 assertive）。注意 Shift+Tab 是修复目标，当前并非可用绕过方式。
高 · 体验+工程核心练习依赖单一 CDN，失败即整体瘫痪
三大判分组件与 9 个 drill 全部从 unpkg 加载 Pyodide 0.29.5，首次 10–20 秒且国内网络易失败；失败后核心练习瘫痪，降级仅一句文字建议。全仓 34 处 CDN 引用无 SRI，加载器重复三套。
建议：本地镜像 + 单例加载器（assets/pyodide-loader.js）+ 重试按钮 + 可复制的离线自测模板；补 integrity。
高 · 工程构建与同步机制实质失效，NOTES 约定与实现不符
构建脚本（20+ 个 tmp_*.py）在被 gitignore 的 .workbuddy/ 中，新 clone 无法复现产物；组件真源是「0004 课件的内联脚本」而非 assets/——改 assets/pyhl.js 后重跑现有脚本不会更新任何新课件，与 NOTES.md:11 直接矛盾。已观测到 base.css 与内联版漂移（打印背景 #fff vs var(--card)）、drill 引擎分化出 4 个变体。
建议：收敛为入库的 tools/build.py，assets/ 为唯一真源，页面只写数据（EX/REVIEW/QUIZ），构建期校验内联块 MD5；先修正 NOTES.md 的失实描述。
高 · 视觉深色偏好下打印输出「浅字白纸」，链路失效
打印块只改 body background、未重置 --ink；系统深色或手动 dark 时 --ink=#e8e4dd，浏览器默认省略背景图形后浅灰字印在白纸上。NOTES.md 明确要求速查表「打印友好」，此路径直接失效。
建议：打印块内重置 --ink/--ink-soft/--accent/--ok/--bad 为深色，并统一 body background:#fff（同步源码与内联版）。

四、分维度其他重要发现

视觉设计

中 浅色 token 偏淡：注释 #98a0ab / #f7f5f2 = 2.43:1、字符串 3.27:1。练习场注释即任务提示，看不清直接阻断作答。建议 tk-com #5f6672、tk-str #2f7d2f、tk-kw #8e1f8b。

中 链接下划线硬编码：#d8c4b4 未变量化，暗底下比链接文字更亮、破坏克制层级，与 NOTES「硬编码浅色已清除」不符。建议改 var(--accent) 或独立令牌。

中 响应式仅 900px 一个断点：大纲 5 列表格无 overflow-x，窄屏挤压；侧注断点过低致 900–1120px 溢出。建议表格横向滚动、≤700px 隐藏「覆盖点」列、侧注断点提到 1200px。

优 底层视觉框架扎实：正文浅/深对比度 17.13:1 / 13.84:1，语义色（ok/bad/warn）映射未错位；42rem 窄栏 + 17px/1.75 + 真 float 侧注的 Tufte 方向明确且 24 页统一。

中 令牌治理：--warn 只在 0000 定义、未进 assets/base.css，未来基于源码生成的页面会静默失效；h3(1.05rem) 小于正文(17px)，层级偏弱。

低 主题按钮用 emoji：多平台字形不一致，与克制纸略有张力，建议改文字 + 纯 CSS 图标。

体验设计

优 教学闭环成立且反馈有教学价值：先答后看带解析 → py-lab 真运行判分 + 参考实现 + 自评 → 间隔复习先写后查 → 大纲进度。防作弊测试（内省签名、可变默认参数累积等）把「懂没懂」变成机器可判据。

优 目标贴合度高：Java 类比贯穿（对照表、心智转变、record/Stream 类比），单课 20–25 分钟契合每晚 1.5h。

中 大纲页脚写死「返回第 9 课」，与「大纲是枢纽」定位矛盾；课数口径不一（14 vs 13），易致「还剩几课」误判。

中 重置不可逆：py-lab 重置直接覆盖代码且无确认，与 drill 的 confirm 不一致（违反 Nielsen 撤销原则）。

中 语义化不足：代码 textarea 无 label/aria-label；quiz 一组 button 无 radiogroup 语义，读屏无法理解「单选」。

中 缺日程级可视化：只有「每 2 天 1 课」模糊节奏，用户每晚仍需回对话问「继续学」；建议加轻量日程或高亮「建议下一课」。

低 文案心理表述不准：「已进长期记忆」易给错误安全感，宜改「明天再来复核一次更稳」。

前端工程

优 判题注入方式安全：用 JSON.stringify 作 Python 字符串字面量，用户代码无法逃逸模板；code 模式用 _lenv=dict(_G) 隔离；39 题缩进与引用全部合规，未发现 XSS 路径。

优 Tab 职责分离、主题逻辑一致：23 页各只有一处 Tab 处理（均来自 pyhl），pylab 明确注释已移交；23/23 页 theme.js 与 assets MD5 相同，无硬编码 data-theme。

优 首屏体积可控：gzip 后大纲 11.9 KB / 普通 drill 18.8 KB / 主课 17.6 KB / 100 题页 24.2 KB；Pyodide 只在点击时加载，无首屏 WASM 开销；23/23 页无 HTML 基础缺陷。

中 重置无法真清空：pyhl 从 wb-code: 恢复本地代码，drill/pylab 重置只清 progress 不清 code 键 → 保存后点「重置」，刷新旧代码复活。另直接赋值 .value 不派发 input，高亮层可能停留在旧内容。

中 判题边界缺运行时校验：tind 原样拼进 try 体、要求严格 8 空格缩进（目前合规但构建期无断言）；expr 的 eval 只捕 Exception，SystemExit 等会穿透；错误直接显示 e.message 可能暴露英文异常。

中 大纲状态逻辑未抽取：lesson-status.js 仅存在于 0000；用 innerHTML 重写进度区导致初始文案「进度以本机浏览器记录为准」首次更新后消失。

低 无障碍细节：动态创建的高亮 pre 未设 aria-hidden（静态烘焙的都设了），将来新增编辑器会让读屏重复朗读。

五、优先级路线图

P0 · 立即修复（阻断核心使用）

恢复判分 + 修默认主题对比度 + 修打印

  • 补回 0007 的 ensurePy，恢复 9 道代码题判分。
  • 按第六节顺序修复 auto-dark 的 token 与按钮对比度（含暗色注释提亮）。
  • 打印块重置前景色并统一背景，恢复打印友好。
P1 · 本周期内（消除高风险与回归源）

  • 统一进度事件，复习加时间戳与「今日待复习」提示；修大纲页脚与课数口径。
  • 放行 Shift+Tab、补焦点态与 aria-live、补 aria-label 与单选组语义。
  • 统一 Pyodide 加载器 + 本地镜像 + 重试与离线降级；重置清理 wb-code: 并派发 input。
P2 · 结构性改造（降低长期扩课成本）

建立单一构建入口 + 统一引擎 + 响应式与令牌治理

  • tools/build.py 入库，assets/ 为唯一真源，页面只写数据，构建期校验 MD5；同步修正 NOTES.md。
  • drill 引擎提为 assets/drill-engine.js，分母统一 EX.length，消除 4 个变体。
  • 表格横向滚动、侧注断点提到 1200px、补 --warn 到 base.css、h3 提字号。

六、关键实施约束：对比度修复的顺序陷阱

⚠️ 两种颜色修复不可分开上线，否则引入作答阻断回归

现状（auto + 系统深色）：CSS 变量已切暗底 #26241f，但 token 因 [data-theme="dark"] 未命中仍用浅色值。此时注释 #98a0ab on 暗底 = 5.87:1（恰好达标），不达标的是关键字/函数/数字/字符串。

若直接把 token 暗色规则扩到 auto 路径：注释会变成暗色 #6b7394 on 暗底 = 3.33:1（从达标跌到 FAIL）——「修好关键字，弄坏注释」。而练习场的注释正是任务提示（如「从 typing 导入 Protocol」），读不清会直接阻断作答。

正确顺序（同批上线）：① 先把暗色 .tk-com 提亮到 #9aa3c7（实测 6.23:1）；② 再把 token 深色规则扩到 @media(prefers-color-scheme:dark) 路径，与变量同源。两步必须一次改动、一次发布。

七、结论

这是一个内容和教学设计明显强于工程底座的产品。对当前唯一用户（作者本人），优先做 P0 三项即可恢复完整可用；若要长期维护并持续加课，必须先补上「assets 单一真源 + 构建校验」这一结构性前提，否则每一次改动都在累积不可见的回归。三份评审一致认为：教学闭环的设计意图是对的，问题几乎全部出在「实现没有完整兑现设计」——主题只做了一半、进度没有连起来、组件真源放错了地方。
