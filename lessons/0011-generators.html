第 11 课 · 生成器与流式输出：yield、迭代器协议与惰性管道

Mission: Python（Agent 开发与面试算法） · 预计 30 分钟 · 关掉 AI 补全再开始

本课的 win：LLM 的 token 是一个一个吐出来的，不是一次性给全——背后的机制就是生成器。验收标准：手写 token 流式输出的生成器，并解释"惰性"为什么省内存。

一、心智模型：生成器 ≈ 惰性的 Stream（4 分钟）

对照 — Java → Python
Stream<T> 惰性求值             →  生成器：要一个才算一个
Iterator / Iterable            →  迭代器协议 __iter__ / __next__
Stream.generate(...)           →  yield 无限流
collect(toList())              →  list(gen)（消费触发计算）
中间操作（map/filter 不执行）   →  生成器管道（串联，照样惰性）

一句本质：生成器是"记住进度的函数"——执行到 yield 暂停、交出一个值，下次从暂停处续跑。不把结果攒成完整列表，内存恒定。

二、yield 基础：暂停与续跑（5 分钟）

PYTHON — yield 的运行模型
def count_up(n):
    i = 1
    while i <= n:
        yield i          # 交出一个值，暂停在这里
        i += 1

g = count_up(3)        # ⚠️ 调用不执行！只返回生成器对象（和协程同一个坑）
next(g)                # 1   ← 执行到第一个 yield 停住
next(g)                # 2   ← 从暂停处续跑
next(g)                # 3
next(g)                # StopIteration ← 流结束信号

for x in count_up(3):  # for 就是 "反复 next 直到 StopIteration" 的语法糖
    print(x)

三、迭代器协议：for 循环的底层（3 分钟）

PYTHON — 手写迭代器（类形态，生成器是它的速记版）
class CountDown:
    def __init__(self, n):
        self.n = n
    def __iter__(self):
        return self
    def __next__(self):
        if self.n <= 0:
            raise StopIteration     # 结束信号
        self.n -= 1
        return self.n + 1

# 有 __iter__ + __next__ 就能 for / list() / in —— 协议即接口（≈ java.util.Iterator）

四、yield from 与 send：委托与双向（5 分钟）

PYTHON — 委托与双向通信
def inner():
    yield 1
    yield 2

def outer():
    yield 0
    yield from inner()   # 委托：把 inner 的产出逐个透传（≈ Stream.flatMap）
    yield 3
# list(outer()) → [0, 1, 2, 3]

def echoer():
    got = yield "准备好了"    # yield 表达式的值 = send 进来的东西
    yield f"收到 {got}"

g = echoer()
next(g)            # "准备好了"（先推进到第一个 yield）
g.send("ping")     # "收到 ping" ← send 的值成为上一个 yield 的结果

# LLM 流式输出的原型：token 一边产、调用方一边消费，不用攒完整回复

五、惰性管道：生成器串生成器（3 分钟）

PYTHON — 管道全程惰性
nums = [1, 2, 3, 4, 5, 6]
evens = (x for x in nums if x % 2 == 0)   # 生成器表达式（≈ filter，还没算）
doubled = (x * 2 for x in evens)          # ≈ map，也还没算
next(doubled)                             # 4 ← 到这一刻才拉第一个元素

参考实现（先自己写完再看）

# 任务 1 — 生成器函数：yield 交出、暂停、续跑
def count_up(n):
    i = 1
    while i <= n:
        yield i
        i += 1

# 任务 2 — token 流：LLM 流式输出的核心形态
def token_stream(text):
    for tok in text.split():
        yield tok

# 任务 3 — 惰性管道：边拉边筛，绝不先攒列表
def even_squares(nums):
    for x in nums:
        if x % 2 == 0:
            yield x * x


自评清单：① count_up 是 while + yield，不是先建列表再 yield 吗？② token_stream 空串返回空流吗？③ even_squares 收到生成器也能拉取吗——探针测试过了吗？





七、检索练习：先答后看（关补全）




  
Q1 · g = count_up(3) 执行后，函数体运行了吗？

  
  
  
  
和协程同款大坑：调用生成器函数只创建生成器对象，一行函数体都不跑。next(g) 或 for 循环才真正推进执行，到 yield 暂停。






  
Q2 · 让自定义对象能被 for 循环，靠什么？

  
  
  
  
for 的底层就是反复调 __next__、捕获 StopIteration 收尾（≈ java.util.Iterator）。生成器函数是这套协议的速记版——函数体里的 yield 自动实现了协议。






  
Q3 · yield from inner() 的效果是？

  
  
  
  
yield from 建立委托：外层生成器把 next 请求转给 inner，产出逐个透传，照样惰性。生成器管道（多个生成器串联）就是这么搭起来的。
