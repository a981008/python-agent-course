二、最小可跑的 FastAPI（4 分钟）

PYTHON — 真实 FastAPI（回本机跑；浏览器判分环境用下面的教学等价物）# pip install "fastapi[standard]"
from fastapi import FastAPI
from pydantic import BaseModel

class ChatIn(BaseModel):
    message: str
    stream: bool = False     # 有默认值 = 可选字段

app = FastAPI()

@app.post("/chat")
async def chat(body: ChatIn):
    return {"reply": f"echo: {body.message}", "stream": body.stream}

# 启动：uvicorn main:app --reload（开发热重载）
# message 传 int、缺字段 → 自动 422 + 错误明细（Pydantic 在路由边界校验）
# /docs 开箱即用的交互文档（OpenAPI 自动生成）

五、动手：MiniAPI 上的完整端点（8 分钟）

浏览器判分环境装不了 FastAPI/uvicorn，预置了形态一致的 MiniAPI：路由表 + 注解校验 + 404/422 语义，和真实 FastAPI 的行为一一对应。三个任务：请求模型（dataclass 形态的 Pydantic）→ 注册异步端点 → 统一错误处理。Ctrl/Cmd + Enter 快捷运行。

先花 1 分钟看懂 MiniAPI 的心脏（判分环境已预置，可直接用）——它只有两样东西：routes 路由表和 call() 模拟请求：

PYTHON — MiniAPI 核心机制（真实 FastAPI 的对应物写在注释里）class MiniAPI:
    def __init__(self):
        self.routes = {}              # 路由表：(方法, 路径) → 处理函数

    def post(self, path):             # @app.post("/chat") 用的就是它
        def deco(fn):
            self.routes[("POST", path)] = fn   # 注册：收到函数记进表
            return fn
        return deco                   # 两层——正是第 13 课的无参装饰器

    async def call(self, method, path, payload=None):
        fn = self.routes.get((method, path))
        if fn is None:
            raise HTTPException(404, ...)   # ① 路由不存在 → 404
        # ② 按端点签名的注解逐个校验 payload：
        #    类型对不上 → 422（真实 FastAPI 由 Pydantic 模型做同一件事）
        #    必填参数缺失 → 422
        return await fn(**kwargs)         # ③ 校验通过才调用端点

class HTTPException(Exception):
    def __init__(self, status, detail):   # 异常对象带 e.status / e.detail
        ...

对照着读：@app.post 的注册本质就是第 13 课的装饰器注册表；任务 1 的请求模型在真实 FastAPI 里是 Pydantic BaseModel（运行时真校验），在 MiniAPI 里退化为 dataclass + 签名注解校验，判分语义一致；任务 3 捕获的 HTTPException 带 status/detail 两个属性（真实 FastAPI 里叫 status_code/detail）。

参考实现（先自己写完再看）

from dataclasses import dataclass

# 任务 1 — 请求模型（真实 FastAPI 里是 Pydantic BaseModel，形态一致）
@dataclass
class ChatIn:
    message: str
    stream: bool = False

# 任务 2 — 异步端点 + 路由注册（注解即校验声明）
@app.post("/chat")
async def chat(message: str, stream: bool = False):
    return {"reply": "echo: " + message, "stream": stream}

# 任务 3 — 统一错误处理：HTTPException → 结构化响应
async def safe(method, path, payload=None):
    try:
        return await app.call(method, path, payload)
    except HTTPException as e:
        return {"status": e.status, "detail": e.detail}


自评清单：① stream 有默认值吗——必填与可选字段分清了吗？② chat 是 async def、注解写了吗（校验靠签名）？③ safe 把 HTTPException 的 status/detail 都带上了吗？





六、检索练习：先答后看（关补全）




  
Q1 · FastAPI 端点写成 async def 的主要收益是？

  
  
  
  
Agent 后端整天在等 LLM API 的网络响应——正是协程主场（第 12 课）。同步 def 端点 FastAPI 也支持，会丢线程池跑；重 IO 的端点才值得 async。






  
Q2 · FastAPI 里类型提示扮演什么角色？

  
  
  
  
纯 Python 的类型提示运行时不校验（第 7 课）；FastAPI 用 Pydantic 把"签名注解 → 请求体校验"自动化了。同一种注解，在 Web 边界从文档升级成防火墙。






  
Q3 · Pydantic BaseModel 和 dataclass 的核心差别？

  
  
  
  
dataclass 是"会生成 __init__ 的类"（第 4 课）；BaseModel 额外在运行时校验类型、能 JSON 互转。校验请求体用 Pydantic，内部数据结构用 dataclass——分工明确。
