一、心智模型：float 是近似，Decimal 是精确（4 分钟）

PYTHON — 官网第 15 章"浮点算术：问题和限制">>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False

# 原因：0.1 在二进制里是无限循环小数，只能用近似值表示。
# 这不是 Python 的 bug —— Java 的 double、C 的 float 都一样（IEEE 754）。

from decimal import Decimal, ROUND_HALF_UP

Decimal("0.1") + Decimal("0.2")     # Decimal('0.3') —— 精确十进制
Decimal(0.1)                        # ✗ 错：把已经近似的 float 转成了精确类型

# 量化到"分"：
Decimal("19.99").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

# 纪律：金额一律用 Decimal，且必须用字符串或整数构造。
# 第 5 课的支付函数用的是 float——本课把它修正过来。
官网 15.1 节"表示性错误"只讲原理；面试追问通常是"那算钱怎么办"——答案就是 Decimal。

二、ExceptionGroup 与 except*（Python 3.11+）（4 分钟）

PYTHON — 官网 8.9 / 8.10 节# 并发任务可能同时失败。3.11 之前只能抛一个，其余信息丢失。

try:
    raise ExceptionGroup("批量失败", [ValueError("a"), KeyError("b")])
except* ValueError as eg:
    print("值错误:", eg.exceptions)     # (ValueError('a'),)
except* KeyError as eg:
    print("键错误:", eg.exceptions)     # (KeyError('b'),)

# except* 不是 except 的别名：
#   每个分支独立处理一类异常，剩下的继续交给后面的 except*
#   和 asyncio.gather(return_exceptions=True) 是天然搭档

# add_note（3.11）：给异常补充上下文，不改异常类型
try:
    1 / 0
except ZeroDivisionError as e:
    e.add_note("分母来自配置文件 config.yaml")
    raise                              # 注意是 raise，不是 raise e

三、pytest：把验证变成可执行的规格（5 分钟）

PYTHON — 官网 10.11"质量控制"# test_pricing.py
from decimal import Decimal
from pricing import money_total

def test_empty():
    assert money_total([]) == Decimal("0.00")

def test_normal():
    assert money_total([Decimal("19.99"), Decimal("0.01")]) == Decimal("20.00")

import pytest
@pytest.mark.parametrize("items,expected", [
    ([], Decimal("0.00")),
    ([Decimal("1.005")], Decimal("1.01")),
])
def test_cases(items, expected):
    assert money_total(items) == expected

# 运行：pytest -q
# 价值：断言失败会打印实际值；用例名就是规格说明；改代码后一键回归。

参考实现（先自己写完再看）

def money_total(prices):
    total = sum(prices, Decimal("0"))
    return total.quantize(CENT, rounding=ROUND_HALF_UP)

def collect_errors(results):
    errs = [RuntimeError(msg) for ok, msg in results if not ok]
    if errs:
        raise ExceptionGroup("批量失败", errs)
    return "ok"

def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError as e:
        e.add_note("分母不能为零")
        raise

五、检索练习：先答后看（关补全）




  
Q1 · 为什么 0.1 + 0.2 == 0.3 是 False？

  
  
  
  
这是 IEEE 754 二进制浮点的表示性错误，Java double 同样如此。金额场景用 decimal.Decimal，并且要用字符串或整数构造。






  
Q2 · except* 和 except 的关键区别是？

  
  
  
  
except* 是 3.11 为 ExceptionGroup 引入的：同一组里不同类型可以各自命中一个分支，未匹配的继续留给后面的 except*。它和 asyncio 并发批量失败天然配套。






  
Q3 · Decimal("0.1") 和 Decimal(0.1) 的区别是？

  
  
  
  
Decimal 从字符串构造时能精确读入十进制位数；从 float 构造则会把二进制近似的真实值（0.1000000000000000055…）原样记下来——所以算钱永远用字符串或整数构造。
