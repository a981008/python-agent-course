二、ReAct 循环：Agent 的心脏（5 分钟）

ReAct = Reason + Act 的循环问题 ──→ LLM 思考："我需要查天气"
     │
     ├─ 行动 ACT     调工具 get_weather("北京")
     │
     ├─ 观察 OBSERVE  工具返回 "北京: 晴 26°C"，追加进对话历史
     │
     └─ 回到 LLM：带着观察再想 → 直到它说 FINAL，循环结束

# 循环每一步都是普通 Python：
#   历史是一个 list[str]（≈ messages 数组）
#   工具分发是 dict[name] + **kwargs（第 13 课注册表 + 第 3 课透传）
#   异常兜底是 try/except（第 5 课）
# MAX_STEPS 步数上限防失控循环——真实 Agent 必备

参考实现（先自己写完再看）

# 任务 1 — 工具函数（@tool 是第 13 课的注册器，预置可复用）
@tool
def get_weather(city):
    return f"{city}: {WEATHER[city]}"

# 任务 2 — 解析 LLM 回复（第 8 课的 json）
def parse_llm(text):
    if text.startswith("CALL "):
        body = text[len("CALL "):]
        name, _, arg_json = body.partition(" ")
        return ("call", name, json.loads(arg_json))
    if text.startswith("FINAL "):
        return ("final", None, text[len("FINAL "):])
    raise ValueError("无法解析的回复: " + text)

# 任务 3 — ReAct 主循环（第 5 课的异常兜底 + 第 13 课的注册表）
def run_react(question):
    context = ["问题: " + question]
    for _ in range(MAX_STEPS):
        kind, name, arg = parse_llm(fake_llm(context))
        if kind == "final":
            return arg
        observation = TOOLS[name](**arg)          # **kwargs 万能透传（第 3 课）
        context.append("观察: " + str(observation))
    raise RuntimeError("步数耗尽")

五、检索练习：先答后看（关补全）




  
Q1 · ReAct 循环里 "Act + Observe" 指的是什么？

  
  
  
  
Act = 从工具注册表分发一次调用；Observe = 把结果 append 进 context（≈ messages）。LLM 每轮都带着全部历史重新思考，直到给出 FINAL。循环体就是普通 Python：list + dict + try/except。






  
Q2 · 工具注册用 @tool 装饰器注册表，最大的好处是？

  
  
  
  
主循环只认 TOOLS 这个 dict：新工具 = 写函数 + @tool。这正是 LangChain/OpenAI function calling 的注册形态，也是第 13 课注册模式的落地。






  
Q3 · 测试里用"脚本化假 LLM"而不是真调 API，为什么？

  
  
  
  
fake_llm 按进度返回脚本化回复，让"调用次数 = 2"这样的断言可精确验证。真实项目里只需把 fake_llm 换成 API 调用——协议（CALL/FINAL）与循环一行不用改。
