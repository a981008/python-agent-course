本课的 win：从"能写函数"升级到"能组织代码"——import 机制、__main__ 守卫、venv 与 pip、typing 全量。验收标准：在 venv 里把练习代码重组为一个可 pip 安装的小项目。

一、心智模型：模块与包 ≈ package 与 classpath（4 分钟）

Python 文件即模块（module ≈ 一个 .java 文件），目录加 __init__.py 即包（package ≈ Java package）。导入体系的 Java 对照：

对照 — Java → Python
import java.util.List;        →  import json              （导入整个模块）
import static Math.max;       →  from math import sqrt    （导入具体名字）
import java.util.*;           →  from math import *       （能用，别写——命名空间污染）
p.println();                  →  json.dumps(x)            （带模块名调用）
classpath（-cp 参数）          →  sys.path（模块搜索路径）
Maven/Gradle 依赖             →  pip + requirements.txt
JAR 包                        →  wheel / pip install 包名

一个关键差别：Python 的 import 是运行时动作——第一次导入会真的执行模块顶层代码并缓存进 sys.modules；两个模块互相导入（循环导入）会在"执行到一半"时炸出 ImportError 或拿到的名字是 None。拆公共部分到第三个模块即可解决。

二、__name__ 与 __main__：Java 没有的入口守卫（4 分钟）

Python 没有 main 方法。每个模块运行时都有一个 __name__ 变量：直接运行该文件时它等于 "__main__"；被别人 import 时它等于模块名。这就是入口守卫：

PYTHON — app.py
def run():
    return "agent 运行中"

if __name__ == "__main__":    # → 相当于 public static void main，但可选
    print(run())

# python app.py      → __name__ == "__main__" → 执行打印
# import app         → __name__ == "app"     → 守卫不执行，只拿到 run

这条守卫让一个文件既能当库被人导入，又能当脚本直接跑——写完的练习代码加上它，就同时是可复用模块和可运行工具。Java 里这需要拆 main 类和库类，Python 一个文件搞定。

三、venv 与 pip：每个项目一个独立 classpath（5 分钟）

Java 一个项目一份依赖；Python 默认全局共享——A 项目要 pydantic 1.x、B 项目要 2.x 就打架。虚拟环境（venv）给每个项目一份独立解释器环境：

SHELL — 三步建环境
python3 -m venv .venv           # 在项目下创建虚拟环境目录
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install pydantic requests   # 装到 .venv 里，不动全局

pip freeze > requirements.txt   # 导出依赖清单（≈ pom.xml 的 dependencies 段）
pip install -r requirements.txt # 按清单还原环境
deactivate                      # 退出虚拟环境

四、typing 全量：从 int 到 Callable（8 分钟）

第 1 课只用了 int/str。工程里会用到的完整套路——运行时不校验，是给人和工具看的（FastAPI/Pydantic 会真的校验，这是 Agent 工程的关键分工）：

PYTHON — 类型提示全家福
# Optional ≈ @Nullable：值可以是 int 或者 None
def find(key: str) -> int | None: ...      # 3.10+ 新写法
def find(key: str) -> Optional[int]: ...   # 旧写法，等价

# 容器泛型：小写内建类直接加方括号（≈ List<Integer>）
def top(items: list[int], n: int = 3) -> list[int]: ...
index: dict[str, int] = {}

# 联合类型：多选一（≈ Object + instanceof 分支，但有名字）
def handle(x: str | int | None) -> str: ...

# Callable：函数类型的类型（≈ Function<Integer, String>）
from typing import Callable
def retry(fn: Callable[[int], bool], times: int) -> bool: ...
# Callable[[参数类型...], 返回类型]

# TypedDict：给 dict 定结构（≈ record 的字典版，Agent 配置常客）
from typing import TypedDict
class AgentConfig(TypedDict):
    model: str
    temperature: float
    tools: list[str]

# TypeAlias：给复杂类型起名
Vector = list[float]

三条纪律：① 新代码用 int | None 小写风格，读旧代码认得 Optional[int] 即可；② 类型提示不影响运行——传错类型照样跑，出错在下游；③ 面试口诀："typing 是文档、mypy 是检查器、Pydantic 是运行时校验，三者分工"。

参考实现（先自己写完再看）

# 任务 1 — Optional 语义 + 解析
def parse_user(raw: str | None) -> dict:
    if raw is None:            # Optional 的 None 分支先行
        return {}
    try:
        parts = dict(p.split("=", 1) for p in raw.split(","))
        return {"name": parts["name"], "age": int(parts["age"])}
    except (ValueError, KeyError):
        return {}

# 任务 2 — TypedDict + 运行时校验
from typing import TypedDict

class AgentConfig(TypedDict):
    model: str
    temperature: float
    tools: list[str]

def validate_config(cfg: AgentConfig) -> list[str]:
    errs = []
    if not isinstance(cfg.get("model"), str):
        errs.append("model 应为 str")
    t = cfg.get("temperature")
    if not isinstance(t, (int, float)) or not (0 <= t <= 2):
        errs.append("temperature 应在 0~2")
    if not isinstance(cfg.get("tools"), list):
        errs.append("tools 应为 list")
    return errs

# 任务 3 — dataclass + 注册表
from dataclasses import dataclass, field

@dataclass
class Tool:
    name: str
    description: str = ""
    tags: list[str] = field(default_factory=list)

def register(registry, tool):
    registry[tool.name] = tool
    return len(registry)


自评清单：① str | None 提示写在签名上了吗？None 分支是先判 None 再解析吗？② TypedDict 三个字段注解对了吗？校验顺序影响错误列表吗？③ tags 用了 field(default_factory=list) 吗——两个 Tool 的 tags 互不影响吗？





三·补、相对导入与字节码缓存（4 分钟）



第 7 课的验收要求"把练习代码重组为可 pip 安装的小项目"，但还差两块：包内部怎么互相导入，以及 import 时磁盘上发生的那件事。



PYTHON — 官网 6.1.3 / 6.4.2 节
# ① 相对导入：包内部用点号定位，不写死包名
#   mypkg/
#     __init__.py
#     core.py          ← 定义 Agent
#     tools/
#       __init__.py
#       format.py      ← 要用上一级包的 Agent

# mypkg/tools/format.py 里写：
from ..core import Agent     # .. = 上一级包（mypkg）
from . import helper         # .  = 当前包（mypkg.tools）

# 两条限制：
#   1. 只能用 from X import Y 形式；from .. import * 是语法错误
#   2. 依赖 __package__，所以直接 python tools/format.py 会失败
#      要用 python -m mypkg.tools.format 从包外启动

# ② 字节码缓存：__pycache__ 与 .pyc
# 首次 import 把编译结果写进 __pycache__/core.cpython-315.pyc
# 下次 import 直接读缓存、跳过编译 → 第二次启动明显更快
# .pyc 是可再生的缓存，可安全删除；Python 版本不匹配会自动重编译
# 项目的 .gitignore 里通常写：__pycache__/  和  *.pyc




  
Q4 · 在 mypkg/tools/format.py 里写 from ..core import Agent，其中 .. 指什么？

  
  
  
  
相对导入的点号是"包层级"而不是文件系统路径：一个点=当前包，两个点=上一级包。它依赖 __package__，所以必须作为包的一部分被导入，直接运行该文件会失败。






  
Q5 · __pycache__ 里的 .pyc 文件是干什么的？

  
  
  
  
.pyc 是 CPython 把源码编译成字节码后的缓存，纯性能优化，删掉不影响正确性。版本不匹配时会自动重新生成，所以不该提交到版本库。





六、检索练习：先答后看（关补全）




  
Q1 · python app.py 直接运行时，if __name__ == "__main__": 里的代码会怎样？

  
  
  
  
直接运行文件时 __name__ 等于 "__main__"，守卫成立；被 import 时 __name__ 等于模块名（如 "app"），守卫不执行。这条守卫让文件既能当库导入、又能当脚本运行。






  
Q2 · venv 虚拟环境最主要解决什么问题？

  
  
  
  
venv ≈ 给每个项目一份独立 classpath。pip install 装进 .venv，pip freeze 导出 requirements.txt（≈ pom.xml 依赖段），换机器 pip install -r 一键还原。






  
Q3 · 函数签名 def f() -> int | None: 的返回值含义是？

  
  
  
  
int | None（旧写法 Optional[int]）≈ @Nullable。注意：纯类型提示运行时【不】校验——传错照样跑；真正在运行时校验的是 Pydantic/FastAPI 这类库。
