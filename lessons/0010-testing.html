本课的 win：把"我觉得对了"变成"机器证明对了"——用普通函数 + assert 写 pytest 用例，覆盖正常、边界、异常三类输入。验收：给第 5 课的支付函数补 5 个用例（正常/边界/异常）并全部通过。

一、心智模型：测试是可执行的规格（3 分钟）

JAVA — JUnit 5 的最小用例class PricingTest {
    @Test
    void emptyCartIsZero() {
        assertEquals(new BigDecimal("0.00"), Pricing.total(List.of()));
    }

    @Test
    void rejectsNegativePrice() {
        assertThrows(IllegalArgumentException.class,
                     () -> Pricing.total(List.of(new BigDecimal("-1"))));
    }
}
PYTHON — pytest：普通函数 + 裸 assertfrom decimal import Decimal
from pricing import money_total

def test_empty_is_zero():
    assert money_total([]) == Decimal("0.00")

def test_normal_sum():
    assert money_total([Decimal("19.99"), Decimal("0.01")]) == Decimal("20.00")

import pytest

def test_rejects_negative():
    with pytest.raises(ValueError):
        money_total([Decimal("-1")])

对应关系：@Test → 函数名以 test_ 开头；assertEquals → assert a == b；assertThrows → with pytest.raises(...)。没有基类、没有注解扫描，pytest 只按命名约定收集用例。

断言失败时 pytest 会展示"期望 vs 实际"的差异，这就是"可执行规格"：用例名说明行为，断言说明边界。

二、pytest 最小面：发现、运行、断言（5 分钟）

SHELL — 三条命令足够日常pytest                  # 发现并运行当前目录全部用例
pytest -q               # 安静模式：只报结果与失败摘要
pytest tests/test_pricing.py::test_empty_is_zero -q   # 只跑一个用例
PYTHON — 断言写"事实"，不写"过程"def test_parse_duration():
    assert parse_duration("1h30m") == 5400
    assert parse_duration("45s") == 45

def test_parse_duration_rejects_garbage():
    with pytest.raises(ValueError, match="格式"):
        parse_duration("abc")

# 一个测试只验证一个行为：失败时一眼知道哪条规格破了。
# 不要在测试里写 print 调试——断言失败信息已经包含实际值。

测试发现规则：文件名 test_*.py 或 *_test.py，函数名 test_ 开头。类名可选（TestXxx），但绝大多数场景不需要类。

三、参数化与异常：把边界表变成用例（5 分钟）

PYTHON — 一张表，多组输入import pytest
from decimal import Decimal

@pytest.mark.parametrize("items,expected", [
    ([], Decimal("0.00")),
    ([Decimal("1.005")], Decimal("1.01")),
    ([Decimal("0.1"), Decimal("0.2")], Decimal("0.30")),
    ([Decimal("19.99"), Decimal("0.01")], Decimal("20.00")),
])
def test_money_total(items, expected):
    assert money_total(items) == expected

# 失败时报告会写明是哪一组参数：
# FAILED test_pricing.py::test_money_total[items1-1.01]

正常值、边界值、异常值，三类都要有。只测正常路径的测试，等于只证明"代码在顺利时能跑"。

JAVA 对照 — 参数化测试@ParameterizedTest
@CsvSource({"0.00, 0.00", "1.005, 1.01"})
void moneyTotal(String items, String expected) { ... }

→ pytest.mark.parametrize("items,expected", [...])

四、fixture 与 tmp_path：真实但隔离的环境（4 分钟）

PYTHON — 用依赖注入代替 setUp/tearDownimport pytest

@pytest.fixture
def sample_lines():
    return ["2026-11-26 INFO user=alice pay", "2026-11-26 ERROR user=bob pay"]

def test_parse_all(sample_lines):
    rows = [parse_line(x) for x in sample_lines]
    assert [r["level"] for r in rows] == ["INFO", "ERROR"]

def test_write_then_read(tmp_path):
    f = tmp_path / "out.txt"
    f.write_text("hello", encoding="utf-8")     # 每个测试独享目录
    assert f.read_text(encoding="utf-8") == "hello"

fixture 就是"测试用的参数由框架注入"：函数签名里写 sample_lines，pytest 自动调用同名 fixture 并把返回值传进来。需要清理的资源放 yield 之后，相当于 JUnit 的 @AfterEach，但作用域更灵活（function/class/module/session）。

PYTHON — yield fixture：准备 → 交出去 → 清理@pytest.fixture
def db_conn():
    conn = connect(":memory:")
    conn.execute("CREATE TABLE t (id INTEGER)")
    yield conn                  # 测试期间可用
    conn.close()                # 测试结束自动清理
Agent 项目里最常见的测试：工具函数的输入输出、ReAct 循环的状态迁移、Prompt 渲染结果。都不需要真连 LLM——把模型调用换成假函数即可。

参考实现（先自己写完再看）

def run_cases(fn, cases):
    passed = failed = 0
    for args, expected in cases:
        try:
            if fn(*args) == expected:
                passed += 1
            else:
                failed += 1
        except Exception:
            failed += 1
    return passed, failed

def expect_raises(exc_type, fn):
    try:
        fn()
    except exc_type as e:
        return e
    except Exception:
        return None
    return None

def assert_close(a, b, tol=1e-9):
    if abs(a - b) <= tol:
        return True
    raise AssertionError(f"期望 {a!r} ≈ {b!r}（容差 {tol}）")


自评清单：① run_cases 里异常是否计为失败？② expect_raises 捕获子类了吗？③ assert_close 失败时消息里有没有实际值？





六、检索练习：先答后看（关补全）




  
Q1 · pytest 默认怎样发现测试函数？

  
  
  
  
pytest 零样板：文件名匹配 test_*.py 或 *_test.py，函数名以 test_ 开头即可。不需要继承类、也不需要专门的 assert 方法。






  
Q2 · 要断言"这段代码必须抛 ValueError"，正确写法是？

  
  
  
  
pytest.raises 同时验证异常类型是否发生；还可以加 match="..." 检查消息内容。手写 try/except 容易漏掉"根本没抛"的情况。






  
Q3 · @pytest.mark.parametrize 的核心价值是？

  
  
  
  
参数化把边界表变成代码：每组参数是一条独立用例，失败时能精确看到哪组输入挂了，不用复制粘贴多个测试函数。






  
Q4 · pytest 的 tmp_path 是什么？

  
  
  
  
tmp_path 由 pytest 注入，每个测试拿到独立目录，适合验证"真的写文件/读文件"，又不会污染仓库或互相干扰。
